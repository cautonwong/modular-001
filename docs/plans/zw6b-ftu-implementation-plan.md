# ZW6B 一二次融合 FTU 实施计划

状态：Draft 0.1，2026-11-23。性能预算标 provisional，以 `docs/plans/zw6b-ftu-performance.md` 为准。

## 1. 目标与范围

目标是把 ZW6B 一二次融合柱上断路器的二次部分做成可量产、可过检、可现场运行的 FTU 产品，并覆盖一次设备接口、FTU 板卡组、嵌入式软件、性能预算和认证。范围包括 12 kV、50 Hz 三相交流配网架空线路，故障检测、隔离、告警、线路监测、非故障段自动复电，测、保、控、通信，频繁操作和恶劣环境。

结论有五条。

1. 复用架构和验证方法，不复用 v8500 硬件平台。现有平台是 Cortex-M0，链接区 256 KiB Flash / 32 KiB RAM，运行时 arena 24 KiB，配单相 RN8209。它无法承载 6 通道 12.8 kHz 采样、保护、101/104、录波和 4G。新 SoC、新板卡组和新 board 是必须的。
2. 复用流程，不复用计量业务代码。FTU 要新建保护、馈线自动化、故障录波、电源管理、设备控制五个限界上下文，不把 DL/T 645、DL/T 698 和计量聚合硬塞进来。
3. 硬件和软件按 HSI 里程碑共同设计，板卡组包括主板、计量 AFE 板、电源板、通信板、背板/航插板。断路器本体、机构、传感器和取能由 OEM 或合作方提供，FTU 方负责接口定义、联调和成套认证。
4. 性能从 Phase 0 就进预算，不在 Phase 4 补测。CPU、跳闸延迟、采样抖动、ROM/RAM、功耗、启动时间、通信时延都要有预算、插桩、门禁和 HIL 证据。
5. 建议在 modular-001 新建 `products/ftu_zw6b` 和 `targets/ftu_zw6b`，条件是 Phase 0 选定 ARM Cortex-M 且 GCC 可构建。硬件 EDA 文件和 OEM 认证材料放 PLM 或受控文档库，不进固件仓库。若选定非 ARM DSP 或供应商专用 IDE，固件改用独立仓库，只共享流程和脚本。

## 4. 硬件工作流

### 4.1 产品边界

一次部分包括断路器本体、真空灭弧室、绝缘、操动机构、电子式互感器、取能模块、航插和电缆。二次部分包括 FTU 板卡组、嵌入式软件、后备电源和本地维护。FTU 方可以只做二次，也可以做一二次融合联调，但必须明确谁对以下事项负责。

- 断路器本体和机构的型式试验报告。
- 传感器变比、精度、相位误差和温度漂移。
- 取能模块的输出曲线、启动电流和后备能力。
- 航插针脚定义、电缆长度、屏蔽和省份差异，基线为 26 芯。
- 一二次融合传动试验和成套入网检测。
- OEM 认证能否复用，还是必须整套重做。

### 4.2 FTU 板卡组

| 板卡 | 功能 | 关键接口 | 待厂商确认 |
|---|---|---|---|
| 主板 | MCU、内存、存储、安全芯片、RTC、看门狗、调试口 | ADC、SPI、I2C、UART、GPIO、DMA、JTAG | MCU 型号、勘误、供货、温度等级 |
| 计量 AFE 板 | 6 通道电压电流调理、抗混叠、ADC、校准存储 | 传感器输入、SPI 或并口、校准 EEPROM | 传感器类型、变比、精度、负载、温漂 |
| 电源板 | CT 取能、PT 输入、超级电容或电池、DC/DC、后备、电源监测 | 24 V 或 12 V、断路器操作、掉电信号 | 取能曲线、后备时长、负 40 度容量、充电时间 |
| 通信板 | 4G、SIM、天线、以太网或光纤、RS485、北斗/GPS | UART、USB、RMII、RS485、PPS | 模块入网许可、SRRC、天线增益、运营商 |
| 背板/航插板 | 一二次融合接口、DI/DO、储能和机构监视 | 航插、继电器输出、光耦输入 | Q/GDW 11815-2023 附录 B/C、151 号、电科院 2026 附件 4 的 26 芯、省份差异、绝缘耐压 |
| 调试/维护板 | 本地维护、指示灯、JTAG、安全口 | UART、USB、JTAG | 维护口认证和禁用策略 |

板卡划分是建议，不是定论。集成度高可以降成本，但调试和认证风险高。分板便于并行开发和替换，但连接器和背板增加成本。这个取舍放 D3。

### 4.5 需厂商确认的硬件事实

- 断路器额定值，12 kV、630 A、20 kA、10000 次机械寿命是否为目标型号的正式参数。
- 机构类型，弹簧或电容，分合闸线圈电压、电流、动作时间，储能电机功率，防跳和联锁逻辑。
- 传感器类型，LPCT、Rogowski 或电子式 VT，变比、精度、相位误差、负载、温度漂移。
- 取能模块启动电流、输出功率曲线、饱和点、后备能力和与电源板的匹配。
- 航插针脚定义、电缆长度、屏蔽、接地和省份差异，按 26 芯基线核对。
- IP 等级、温度范围、海拔、污秽等级、盐雾、紫外和振动。
- EMC 等级，按 DL/T 721-2024、Q/GDW 10514-2018、Q/GDW 10639 和目标省份检测公告。
- OEM 型式试验报告覆盖的型号、参数、试验项目和有效期。
- 4G 模块入网许可、SRRC 型号核准、天线增益和运营商兼容性。
- 安全芯片认证、密钥注入流程和供货。
- 超级电容或电池在负 40 度和高温下的容量、寿命和充电时间。
- PCB 供应商的阻抗控制、涂覆、拼板和交期。
- 外壳材料、密封、接地和防腐蚀。

### 4.6 型式试验与一二次融合

型式试验包括 EMC、环境、IP、介电、温升、机械寿命、电源影响、振动、冲击、盐雾和外壳。具体项目和等级按 DL/T 721-2024、Q/GDW 10514-2018、Q/GDW 10639、Q/GDW 11253-2023 和目标省份公告。本文不声称这些试验已经通过。

一二次融合联调包括 26 芯航插对接、传感器变比核对、取能供电、断路器分合闸、储能、防跳、联锁、辅助触点、位置信号、故障模拟和主站联调。联调报告要由双方签字，并列出未关闭项。入网检测按成套设备送检，样机数量和批次按目标省份公告。

OEM 认证策略有三种。复用 OEM 本体型式试验报告并补成套差异项。整套重做型式试验。先做关键项预试，再按入网要求补全。选哪种取决于 OEM 报告覆盖范围和目标省份要求，放 D14。

### 5.2 插桩与测量

- host 仿真计数，统计算法周期、状态机跳转、分配次数和路径覆盖。
- target 周期计数，用 Cortex-M 的 DWT CYCCNT、GPIO 翻转和 SWO/ITM。
- 逻辑分析仪，测 SPI、I2C、UART、ADC 采样和出口时序。
- 功率分析仪，测典型、峰值、4G 突发、后备和温度点。
- HIL，继保测试仪注入故障，断路器模拟器或真机构动作，主站记录端到端时间。
- 4G 模块日志、主站时间戳和北斗/GPS PPS，测附着、重连和对时。

### 5.3 基准与回归门禁

| 门禁 | 内容 | 失败动作 |
|---|---|---|
| host 仿真计数 | 算法周期、状态机、分配次数不超过基线 | CI 失败，禁止合入 |
| target 周期计数 | ISR、DFT、任务抖动不超过预算 | 夜间构建失败，进缺陷列表 |
| HIL 时序 | 跳闸延迟、FA 端到端、SOE、通信响应 | 发布门禁失败 |
| ROM/RAM | ELF section、链接断言、栈使用 | 链接失败或 CI 失败 |
| 功耗 | 典型、峰值、后备、温度点 | 性能评审不通过 |
| 启动时间 | 冷启动、热启动、OTA 后启动 | 发布门禁失败 |

### 5.4 只能 HIL 验证的指标

- 保护跳闸延迟，从故障注入到物理出口和断路器动作。
- CT 饱和、直流分量、谐波和涌流下的保护动态性能。
- 温度点功耗、4G 峰值、后备时间和充电时间。
- 掉电唤醒、通信恢复和主站重连。
- 4G 附着时间、信号弱场景和运营商切换。
- 北斗/GPS 对时精度和 SOE 时标。

host 仿真能验证算法周期、状态机、协议编解码和内存使用，不能替代模拟前端、真实电源、真实断路器、真实无线和真实温度。

## 8. 关键路径

关键路径是，Phase 0 标准、客户需求、OEM 选择和硬件架构，Phase 1 板卡打样和 bring-up，Phase 2 EVT1 和一二次融合接口冻结，Phase 3 EVT2 和主站集成，Phase 5 型式试验、入网、试点、移交。

长周期项有五类。OEM 断路器样机和认证 8 至 16 周。SoC、4G、安全芯片采购 12 至 16 周。PCB 每次改板 6 至 8 周。模具 8 至 12 周。实验室排期 8 至 12 周。试点审批 4 至 8 周。

可以并行的有三条。协议栈先在 host 上开发和一致性测试。FA 状态机和 TLA+ 模型在 Phase 2 末开始。生产工装和认证文档在 Phase 4 与 DVT 并行。性能门禁贯穿各阶段，跳闸延迟、功耗、启动、ROM/RAM 任何一项不达标都可能阻塞发布。

## 12. 仓库建议

建议在 modular-001 内新建 `products/ftu_zw6b/product.yaml` 和 `targets/ftu_zw6b`，作为第 8 个产品、第 4 个固件 target。条件是 D4 选定 ARM Cortex-M，且 arm-none-eabi GCC 能构建。

理由有四条。

1. 复用成本最高的部分，分层、端口、组合根、产品清单、CI、验收、形式化、HIL 方法都在这个仓库。
2. `docs/ROADMAP.md` 的 P2.4 明确要第二个 SoC 和板型来验证平台。FTU 就是第二个产品。
3. 新 target 由 `ci_matrix.py` 自动发现，验收矩阵和 ROM/RAM 检查可以按产品隔离。
4. 团队只有一套验证文化，一套提交和评审习惯。

硬件不放进固件仓库。原理图、PCB、BOM、器件库和 OEM 认证材料放 PLM 或受控文档库，`docs/plans/zw6b-ftu-hardware.md` 作为入口和接口摘要。固件仓库只放接口定义、端口适配、测试和 HIL 脚本。若一定要把硬件文档放仓库，只放 Markdown 和 PDF 摘要，不放二进制 EDA 文件。

必须满足四条约束。

- FTU 用新的限界上下文，`domain.protection`、`domain.feeder_automation`、`domain.fault_recording`、`domain.power`、`domain.device_control`，不在计量 domain 加条件编译。
- FTU 不把 DL/T 645、DL/T 698 当主协议，也不复用计量聚合和 ESAM 驱动。
- FTU 有自己的 ROM/RAM/功耗预算、验收矩阵和 `tools/check_ftu_firmware.py`，不共用 IDIS 的 103 KiB 保证。
- 保护路径用静态分配，不依赖堆和 RTOS 调度。ISR 需要一个初始化后只读的根指针，按 `mutable_globals_exceptions.txt` 写理由、到期日和批准人。

什么时候改用独立仓库。选定非 ARM DSP 或供应商专用 IDE，例如 C2000/CCS 或 Blackfin/CCES。业务单元需要独立访问控制、独立发布节奏或独立客户交付。客户要求把 FTU 固件作为独立可交付物。出现这三种情况时，独立仓库更干净，只共享流程文档和检查脚本。

不建议把 FTU 放进 `targets/stategrid_meter`，也不建议为了复用在计量 domain 里加 `#ifdef`。

## 13. 验证证据

每个阶段结束必须有可重跑的证据，不以“编译通过”或“演示过”作为完成。

- `./ci.sh` 全绿，包含新 target 的 host 单测、strict、analyzer、sim-san。
- 新 target 验收 `verdict=clean`，用例数在验收矩阵登记。

- ELF section 实测数字与预算对比，链接脚本有断言，栈使用有 `-fstack-usage`。
- HIL 日志，包含继保测试仪、断路器模拟器、主站模拟器、北斗/GPS 和功率分析仪。
- 硬件 bring-up、单板测试、HSI-1 至 HSI-8、预兼容、型式试验、一二次融合联调、入网报告。
- 性能基线、target 周期计数、host 仿真计数、功耗、启动、OTA 和现场报告。
- `[clean-clone] ok`。

需要新增的仓库资产。

- `products/ftu_zw6b/product.yaml` 和 `targets/ftu_zw6b/{app,board,config,build,tests}`。

- `tools/mutable_globals_frozen.txt` 和 public struct 基线按新 target 增量。

## 14. 原则说明

- Attack the Premise。把“现有 v8500 平台可直接承载 FTU”写成前提，用 256 KiB / 32 KiB、24 KiB arena、Cortex-M0 和缺失的三相保护代码检验，结论为假。新 SoC、新板卡组和 HSI 里程碑因此进入关键路径。
- Redesign from First Principles。把 FTU 当成从零设计的新产品，先定硬件板卡组、五个限界上下文、HSI 和性能预算，再决定复用。结果是新增 domain、protocol 和硬件工作流，不在计量 domain 上打补丁。
- Laziness Protocol。没有提议复用 645/698 和计量聚合，没有提议通用驱动模型，没有在 v1 塞完整 860。协议栈优先买或借，FA 模式按客户强制范围裁剪，板卡按调试需要分板。
- Sequence Verifiable Units。每个阶段有进入和退出证据，HSI-0 至 HSI-8 各自可验收，性能门禁从 Phase 1 就进 CI 或夜间，不合格不进入下一阶段。
- Outcome-Oriented Execution。阶段边界明确，v1 范围裁剪是产品决策，不保留临时兼容层。认证样机只从冻结版本出。

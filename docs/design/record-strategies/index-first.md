# 策略：自然顺序窗口（index/plan-first）

状态：设计完成，未实现。候选实现于 2026-11-19 的 arena，形式化件可构建；
选型时让位于 cache-first，原因是 ROM 和表头时间不变量。

## 问题

选择性查询（时间/值区间）在只有线性扫描时，count 和 write 两趟都要读所有
记录。环按 append 顺序存，记录头带 append 时间；这个顺序本身就是一个索引。

## 算法

1. 暴露 `header_time(slot)`：读 20 B 记录头，不解 payload。
2. 每环维护一个 1 bit 单调标志：恢复时顺带计算；每次 append 只多读 20 B
   前一记录头；回拨 append 清标志；启动重算。非单调时退回线性扫描。
3. 对时间区间做两次下界搜索（二分），得到连续窗口 `{first, count}`；
   PROFILE 的容量和扇区布局保证窗口内槽位可 O(1) 定位。
4. 写响应前用真实时钟列校验窗口边界最多 4 行；`exact = 0` 表示策略放弃，
   调用方走线性扫描。
5. 非时间列的值区间没有单调性，退化为线性扫描（每行一次读，谓词与输出共用）。

## 接口

两函数端口：`plan(selection) -> {first, count, exact}` 和
`read(row) -> record`。游标由 plan 的窗口表示，block transfer 直接按窗口分页。

## 成本（1152 行 PQ，M = 匹配数）

| 查询 | 线性（今天） | 本策略 |
| --- | --- | --- |
| 时间区间，M=1 | 2304 | 27 |
| 时间区间，M=N | 2304 | 1178 |
| 非时间区间 | 2N | 2N |

RAM +88 B（22 个容量的标志对齐）加 4 B 端口指针；ROM 实测 0.6-0.8 KiB 估计。
append 多一次 20 B 读，无新增 program/erase。

## 失败模式与前置条件

- **表头时间必须等于时钟捕获列。** 当前采集写 `now->time`
  （`nd_idis_profile.c:114`），时钟列是另一个端口读（`:75-92`）；二者可能不同，
  4 行边界校验抓不住内部发散，会静默返回错误的行集。在采集改为写时钟列之前，
  快路径必须 `exact = 0`。
- 降序时间排序必须先检查单调标志，否则回拨后不是时间序。
- 窗口外的损坏记录不再导致整次查询失败（行为变化）；线性端口保留旧口径。
- 满环之后的窗口与并发 append 竞争时，需要 snapshot 规则（见 cursor-first）。

## 目标组合

IDIS：作为 cache-first 之上的一层；探针和行读都被 4 KiB 窗口缓存。绑定点是
COSEM profile generic 的消费者；关闭时绑定线性端口，行为与今天一致。

## 测试（设计）

- 仪器化 read 计数：27 / 1178 / 2N 的断言。
- 单调标志：回拨、跨重启、断电撕裂。
- 边界校验：内部行与表头时间不一致时的 fail-closed。
- 既有 COSEM GET 验收逐字节比对。
- 形式化：Lean 的环/搜索界，CBMC 的 header 探针边界，TLA+ 的 plan 不变量。
